# Spec Delta

## Purpose

让模型在工作中发现、安装和使用新能力，不因资源变化重启会话。配置、MCP、skill 和 prompt 有可查询的来源与版本，能力目录实时更新，已开始的调用保持稳定，更新失败仍能使用最后的可用版本。

## ADDED Requirements

### Requirement: 配置隔离与有效来源可查询

系统 SHALL 隔离不同配置档的有效设置和状态，提供有效配置、覆盖来源及校验错误查询。无效更新 MUST NOT 替换最后有效配置；凭据 SHALL 使用环境或外部存储引用，普通配置快照、事件与导出 MUST NOT 保存凭据值。

#### Scenario: 项目覆盖用户配置

- **WHEN** 用户配置与项目覆盖定义同一项，再提交无效更新
- **THEN** 查询能够解释有效值的来源；无效更新被拒绝，原有效值仍可使用，其他配置档不受影响

### Requirement: 固定已开始的请求与调用

系统 SHALL 保存任务启动配置，并为每次模型请求及工具调用记录实际资源版本。已发出请求和正在运行的调用 MUST NOT 被热更新替换；新能力目录 MUST NOT 被整个任务的启动快照锁死。

#### Scenario: 旧调用运行时更新能力

- **WHEN** 调用正在执行，同时发布其新定义或新增其他能力
- **THEN** 旧调用继续绑定原版本；下一次发现、读取或调用能够使用新发布能力，记录能区分实际版本

### Requirement: 能力更新与运行选择分开

系统 SHALL 让就绪能力在当前任务可发现和显式选用，但默认模型、cwd 等运行选择 MUST NOT 因配置刷新静默改变当前任务。新任务 SHALL 使用最新默认值，用户或模型显式变更 SHALL 作用于后续合法请求。

#### Scenario: 工作中新增 provider 并修改默认模型

- **WHEN** 一个任务执行期间新增 provider 并改变默认模型配置
- **THEN** 新 provider 可立即被显式选择，当前任务不会自动换模型或 cwd，新任务读取新默认值

### Requirement: MCP 默认搜索后调用

系统 SHALL 管理独立 MCP 目录，默认只向模型提供稳定搜索与执行入口，不展开全部工具定义。搜索 SHALL 返回工具引用、描述、输入 schema 和目录版本；执行 SHALL 接收引用及参数，返回内容、附件或明确错误。

#### Scenario: 搜索后执行外部工具

- **WHEN** 模型尚未看到某 MCP 工具完整定义，先按问题搜索再调用
- **THEN** 搜索给出有预算和分页限制的匹配定义，随后调用实际工具，其他未选工具不被强制注入上下文

### Requirement: 工具引用绑定定义版本

系统 SHALL 将 `tool_ref` 绑定实际工具与定义版本。目标删除或替换后，旧版本不可用 SHALL 返回 stale-reference 并要求重新搜索，MUST NOT 将旧引用静默映射到新定义；仅新增无关能力 MUST NOT 使所有旧引用失效。

#### Scenario: 替换搜索过的工具

- **WHEN** 模型持有旧引用，目标更新且旧版本已不可用
- **THEN** 调用返回引用过期及重新发现指引，不以新 schema 执行旧参数；已有运行调用仍按原版本处理

#### Scenario: 目录新增无关工具

- **WHEN** 搜索后目录只增加另一个工具
- **THEN** 原目标未变化时原引用继续可用，不强迫重新搜索整个目录

### Requirement: 四协议都有 MCP 可用路径

系统 SHALL 为四种模型协议提供 host 搜索调用闭环；具体接入已确认支持原生 deferred/tool search 时 SHALL 默认采用其原生机制。两条路径 SHALL 保持相同的调用身份、资源版本与错误语义，不以品牌名称推断支持。

#### Scenario: 原生与兼容接入完成同一任务

- **WHEN** 分别使用已验证的原生接入和无原生字段的兼容接入执行搜索调用
- **THEN** 前者使用协议支持的原生机制，后者使用 host 入口；两者均能记录并返回同一工具的调用结果

### Requirement: 安装与刷新必须报告真实就绪

系统 SHALL 向模型公开注册、刷新和就绪查询入口，并发现受管理目录的外部变更。资源 SHALL 在完整性、依赖、解析及必要连接成功后原子发布；下载完成、半写文件或缺少凭据 MUST NOT 被报告为可用。

#### Scenario: 在当前任务安装 MCP

- **WHEN** 模型完成安装、注册并等待服务连接就绪
- **THEN** 同一任务可以立即搜索和调用，不要求重启或先输出 final；未就绪时返回具体状态或错误

#### Scenario: 外部程序分多次写入资源

- **WHEN** 文件监视器观察到尚未完整的配置或 skill 文件
- **THEN** 系统不发布半成品，完整且校验通过后再通知；失败保留原可用版本

### Requirement: skill 作为可发现资源使用

系统 SHALL 在 skill 就绪后提供名称、描述、正文和资源读取入口，由模型读正文后使用；脚本仍通过进程能力执行。skill MUST NOT 被建模为包揽发现到回收的后台任务，使用时 SHALL 保留资源来源与版本。

#### Scenario: 当前任务安装和更新 skill

- **WHEN** 新 skill 或新版正文发布就绪
- **THEN** 模型同一任务即可发现并读取，后续使用关联所读版本，既有历史中的旧说明保持不变

### Requirement: prompt 与能力变更追加通知

系统 SHALL 将资源发布结果作为有界、带来源的变更通知追加到历史，prompt 更新 SHALL 以新增指令或资源读取表达。系统 MUST NOT 原地替换过去的 skill 列表、prompt 或工具结果，也 MUST NOT 用完整 MCP 目录挤占每次上下文。

#### Scenario: 连续安装多项资源

- **WHEN** 一项任务期间发布多个 MCP、skill 或 prompt 版本
- **THEN** 模型收到可查询详情的有界变化通知，能发现最新能力，原历史和正在执行的调用保持稳定
