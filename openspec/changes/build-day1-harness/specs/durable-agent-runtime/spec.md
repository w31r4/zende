# Spec Delta

## Purpose

让 Agent 作为持续会话在界面之外工作，用户断开连接或核心故障后仍能接回已有任务。本能力约定任务身份、停止范围、请求去重和恢复结果，避免把一次 CLI 返回、模型响应或界面退出误认为任务生命周期。

## ADDED Requirements

### Requirement: Agent 生命周期独立于客户端

系统 SHALL 保存持续的 `agent_id`，为每项工作分配独立 `task_id`；同一 Agent 同时最多运行一条模型循环。客户端断开 MUST NOT 停止 Agent、子 Agent 或进程，任务完成 MUST NOT 销毁会话。

#### Scenario: 关闭 TUI 后接回同一任务

- **WHEN** 用户在 Agent 执行长命令时关闭并重新打开 TUI
- **THEN** Agent、任务和进程身份保持不变，工作继续，客户端可以补读断线期间的输出

#### Scenario: 持续会话接受第二项工作

- **WHEN** 已完成任务的 Agent 接收新工作
- **THEN** 系统创建新任务并保留原历史与 mailbox，不同时开启第二条模型循环

### Requirement: 持久接受与请求去重

系统 SHALL 在持久保存请求和关联身份之后才确认接受，并按稳定请求 ID 去重。接受状态、工具完成和任务终态 SHALL 分别可查询；CLI 退出成功 MUST NOT 被解释为任务完成。

#### Scenario: 提交超时后重试

- **WHEN** 客户端未收到接收确认，使用同一请求 ID 重试
- **THEN** 系统返回原接收记录和任务或消息身份，不再创建重复工作

#### Scenario: 核心离线时提交

- **WHEN** core 不在线且请求未被持久接受
- **THEN** 客户端报告未接受或接收状态未知，不假报成功；重连后可按同一请求 ID 核实

### Requirement: 停止当前 Agent 与停止全部分开

系统 SHALL 将停止当前 Agent 解释为取消当前任务并进入人工暂停，默认保留子 Agent 和已移交的后台进程。无法立即取消的调用 SHALL 显示取消处理中；停止全部 SHALL 使用显式目标范围。

#### Scenario: 停止父 Agent 时子任务继续

- **WHEN** 用户停止父 Agent，随后子 Agent 完成并投递结果
- **THEN** 父任务取消结束后保持 `cancelled`，父 Agent 保持暂停，子结果持久保存且不解除暂停

#### Scenario: 不可立即取消的操作

- **WHEN** 停止请求到达时某调用尚不能确认终止
- **THEN** 系统显示取消处理中和关联调用，不报告全部已停止，也不声称回滚已发生的外部效果

### Requirement: 恢复暂停不改写旧任务

系统 SHALL 通过显式 resume 或用户新输入解除人工暂停，不复活已取消的任务。resume SHALL 按接收顺序处理待投递消息，无消息时创建续接任务；用户新输入 SHALL 开启新任务，其余 queue 消息随后处理。

#### Scenario: 显式恢复暂停会话

- **WHEN** 用户对已取消任务的 Agent 执行 resume
- **THEN** 系统以新的任务身份继续处理，旧任务终态和取消记录保持不变

### Requirement: 已知工作自动恢复

系统 SHALL 在 core 重启后恢复已接受请求、会话、mailbox、资源版本和可关联的进程。存活进程 SHALL 按持久身份重新连接；已丢失进程 SHALL 明确报告，保留历史和已落盘结果，不要求用户重述完整任务。

#### Scenario: 工具派发前或运行中崩溃

- **WHEN** core 在输入已接受但尚未派发工具，或工具已在独立进程中运行时退出
- **THEN** 恢复后分别继续原任务或关联原进程，不重复创建任务或重启仍在执行的命令

#### Scenario: 机器重启导致进程丢失

- **WHEN** 恢复时原进程已不存在
- **THEN** 系统报告进程丢失和最后可读输出，不伪称恢复进程内存或成功执行

### Requirement: 未知副作用先核实

系统 SHALL 将可能已执行但结果缺失的操作标记为待核实，通过进程终态、幂等查询或产物检查确认后继续。不能证明可安全重复时 MUST NOT 自动重放该副作用，包括更换调用 ID 或让模型再次提出等价操作。

#### Scenario: 操作生效后结果未落盘

- **WHEN** 外部操作可能已成功，而 core 未保存结果便崩溃
- **THEN** 恢复流程先展示原操作及不确定性并提供核实入口；无法确认时保留待处理状态，不自动重复操作

### Requirement: 语义事件可关联和补发

系统 SHALL 为会话语义事件提供协议版本、`agent_id`、会话内单调递增 `seq`、类型和 payload，按需携带任务及调用身份。查询状态与订阅 SHALL 提供一致的事件位置，重连 SHALL 支持游标补发及去重，不能重放副作用。

#### Scenario: 状态查询期间继续产生事件

- **WHEN** 客户端获取状态、连接订阅或在断线后按游标重连
- **THEN** 状态与后续事件之间没有未说明的缺口，重复事件按 seq 去重；不可补发的范围返回明确缺口说明

### Requirement: 资源限制可查询且不代替权限策略

系统 SHALL 公开并发、递归、输出保存和重试限制，达到限制时返回可恢复状态及原因；清理 MUST NOT 静默删除仍被上下文或未完成任务引用的内容。Day1 工具和插件 SHALL 按当前用户能力执行，不增加审批或沙箱步骤。

#### Scenario: 达到运行限额

- **WHEN** 新工作超过配置的并发或输出保留限制
- **THEN** 系统报告具体限制及现有工作状态，不清空会话、不假报执行成功，也不把限额错误包装成权限审批

### Requirement: 会话复制保留历史并停止源工作

明确确认的会话复制 SHALL 创建新 Agent，复制完整历史、当前上下文视图、附件和草稿并采用新 cwd，保留源历史。系统 SHALL 先冻结源会话调度，停止其所属 Agent 树、任务及 tmux/pipe，核实终态后才发布可继续的新副本；MUST NOT 克隆活动进程或重放已完成副作用。源会话 SHALL 保留为只读历史，此流程不改变普通 stop 和 detach 语义。

#### Scenario: 复制有后台工作的会话

- **WHEN** 用户确认将有子 Agent、Task 和 tmux 的会话复制到新目录
- **THEN** 原工作全部停止，历史可查，新副本拥有独立身份、完整上下文及新 cwd，只有新副本可继续

#### Scenario: 停止失败或复制提交时崩溃

- **WHEN** 复制过程中某终态未知、停止失败或 core 退出
- **THEN** 复制操作保持可查询状态并按原请求 ID 恢复；新副本未发布前不启动新工作，不丢源历史、不重复创建副本
